# RTL Design Guide

This document describes the synthesizable RTL used by the programmable processor.
The canonical implementation is split across the directories below. Quartus-generated
memory wrappers are kept separate from the handwritten control and datapath logic.

## RTL organization

| Directory | Modules | Responsibility |
| --- | --- | --- |
| `Project/` | `Project`, `Processor` | Board wrapper and processor integration |
| `Control_Unit/` | `Control_Unit`, `FSM`, `IR` | Instruction fetch, decode, sequencing, and control outputs |
| `Datapath/` | `Datapath`, `RegFile`, `ALU`, `RAM`, `mux16w_2to1` | Register storage, arithmetic/logic, memory access, and writeback |
| `ROM/` | `myROM` | Quartus-generated instruction memory |
| `RAM/` | `myRAM` | Quartus-generated data memory |
| `Board/` | `Decoder`, `KeyFilter` | Active-low HEX display decoding and manual clock stepping |

`RegALU/` contains an earlier standalone register-file/ALU integration used during
development. It is not part of the processor build in `runrtl.do`.

## Processor hierarchy

```text
Project
`-- Processor
    |-- Control_Unit
    |   |-- FSM
    |   |-- IR
    |   `-- myROM
    `-- Datapath
        |-- RegFile
        |-- ALU
        |-- RAM
        |   `-- myRAM
        `-- mux16w_2to1
```

`Processor` exposes debug outputs for simulation and board display: the current
instruction (`IR_Out`), program counter (`PC_Out`), current and next FSM states,
and the ALU operands/result.

## Clock and reset conventions

- `Processor.ResetN` is active-low. `0` holds the processor in reset and `1` runs it.
- `Control_Unit.Rst` is active-high and is inverted before it reaches `FSM.ResetN`.
- `Project` uses active-low `KEY[1]` as `ResetN`.
- `Project` filters active-low `KEY[2]` and uses the resulting pulse as the processor
  clock. Normal simulation uses the clock generated by the testbench instead.
- The FSM is Moore-style control logic. Outputs receive safe defaults in the
  combinational block, and the state register changes on the rising clock edge.

## Register file and program counter

The datapath register file has sixteen 16-bit entries:

- `R0` reads as zero and ignores writes.
- `R1` through `R14` are general-purpose registers.
- `R15` (`4'hF`) stores the program counter.

The dedicated PC controls have priority over a normal register write:

1. `PC_clr`
2. `PC_w_en` with `PC_set`
3. `PC_up`
4. regular register-file write

Register-file reads and the ALU are combinational. Register writes and PC updates
occur on the rising edge of `Clk`.

## Instruction and ALU encodings

The opcode is `IR_data[15:12]`.

| Opcode | Instruction | Description |
| --- | --- | --- |
| `0` | `SHR` | Shift A right by the immediate shift amount |
| `1` | `STORE` | Write a register value to data memory |
| `2` | `LOAD` | Read data memory and write it to a register |
| `3` | `ADD` | Add two register values |
| `4` | `SUB` | Subtract B from A |
| `5` | `HALT` | Remain in the halt state |
| `6` | `MOVI` | Replace the low byte of A with the 8-bit immediate |
| `7` | `OR` | Bitwise OR |
| `8` | `AND` | Bitwise AND; `AND R0,R0,R0` is the NOP encoding |
| `9` | `JMP` | PC-relative jump using a signed 12-bit offset |
| `A` | `JNZ` | Conditional jump to `RF[B] +` signed 4-bit offset when `RF[A] != 0` |
| `B` | `JLT` | PC-relative signed-less-than jump using a signed 4-bit offset |
| `C` | `SHL` | Shift A left by the immediate shift amount |
| `D` | `MULT` | Multiply two register values |
| `E` | `CMP/SETcc` | Capture comparison flags or write a conditional Boolean |
| `F` | Reserved | Not currently assigned by the FSM |

The datapath ALU select `Alu_s0` uses the same ordering as the FSM:
`000=SHR`, `001=ADD`, `010=SUB`, `011=MULT`, `100=MOVI`,
`101=OR`, `110=AND`, and `111=SHL`.

`CMP` stores zero, negative, and overflow status in the control/datapath flag
registers. `SETcc` consumes those stored flags and writes `0000` or `0001`;
conditions `SETLT`, `SETEQ`, `SETNE`, `SETLE`, `SETGT`, and `SETGE` use codes
`0` through `5`.

The top-level assembler treats jump labels and bare numeric jump targets as
full 16-bit absolute instruction addresses. It materializes those targets with
the existing `MOVI`/`SHL`/`MOVI`/`OR` sequence and writes the result to `PC`
through the ALU path. Explicit `+offset`/`-offset` operands retain the compact
native relative encodings. Conditional pseudo-jumps use a short condition guard
followed by the same full-address transfer.

## Memory interfaces

`Control_Unit` addresses `myROM` with the live PC, except during a PC write when
the jump target is selected. The instruction is latched into `IR` during `FETCH`.

`Datapath.RAM` wraps the Quartus-generated `myRAM` interface:

```text
address[15:0], clock, data[15:0], wren, q[15:0]
```

Only the low address bits used by the generated memory determine the RAM location.
The RAM output is selected for register writeback when `RF_s=1`; ALU output is
selected when `RF_s=0`.

## Simulation and maintenance

From the repository root, open ModelSim/Questa and run:

```tcl
do runrtl.do
```

This script compiles the current project hierarchy and runs `testProcessor`.
For the individual FSM testbench, use `Control_Unit/run_FSM_tb.do`.
`run_all_tests.do` is the broader regression script and includes the module
testbenches embedded in the RTL source files.

The main processor test expects the initialized program to reach `STORE` with
address `6A` and value `4199`, then reach `HALT` with instruction `16'h5000`.
When changing an interface or instruction encoding, update the FSM, datapath,
memory initialization files, relevant testbench, and this document together.
